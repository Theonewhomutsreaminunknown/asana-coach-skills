# Contributing

Improvements are welcome, especially corrections when Asana changes a feature or limit.

## Guidelines
- Keep skills beginner-friendly: explain terms once, in plain language, with an example.
- Keep each `SKILL.md` focused on its stage; shared reference material goes in `docs/best-practices.md`.
- Skill frontmatter needs `name` (kebab-case, matching the folder) and a one-sentence `description` that says when to use it.
- If you add a limit or quirk, say what plan you saw it on and when.
- Don't include organization-specific names, IDs or people.
- Log notable changes in `CHANGELOG.md`.

## Ideas for future skills
- Goals and KPI scorecards (strategic plan → goals → portfolios → status reviews)
- Templates and recurring work (project templates, recurring events)
- Integrations (email, chat, forms tools) and when to use an automation platform
